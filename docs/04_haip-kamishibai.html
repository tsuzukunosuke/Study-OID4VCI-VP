はいぷ先生こんにちは! ぼくは「はいぷ先生」。デジタルしょうめいしょの せかいの、あたらしい おやくそくの ほんだよ。みんなで よんでいこう!

おとなのことばHAIP = OpenID4VC High Assurance Interoperability Profile 1.0。OID4VCI / OID4VP の「高保証プロファイル」で、2025 年 12 月に Final(確定版)になりました。英語圏では「ハイプ」と読まれます。

おとなのことばIssuer(発行者)/ Holder(ウォレット)/ Verifier(検証者)の 3 者モデル。VC には発行者の電子署名が入っており、検証時に発行者へ問い合わせる必要はありません(→ 基礎ドキュメント①)。

おとなのことばOID4VCI / OID4VP は汎用プロトコルで、フォーマット・鍵解決・レスポンスモード等に選択肢が多く、双方とも仕様準拠なのに相互接続できないことが起こり得ました。これが HAIP が生まれた理由です。

はいぷ先生 とうじょう!

✦ ✦

はいぷ先生だいじょうぶ! この ルールブックには 「まよったら こうする」が ぜんぶ 1つに きめてあるんだ。みんなが この ほんの とおりに すれば、はじめて あった ウォレットと もんばんさんでも、かならず おはなしできるよ!

はいぷ先生2025ねんの 12がつに かんせいした、できたての ほんなんだ。おやくそくは 6つ。じゅんばんに みていこう!

おとなのことばHAIP はオプションを絞り込んで必須化する「プロファイル」です。EUDI Wallet(EU デジタル ID ウォレット)のエコシステムとも方向性が揃っており、HAIP 準拠がグローバル相互運用の共通土台になります。
おやくそく その1

カードの かたちは 2しゅるい だけ

おてがみがた
(SD-JWT VC)
めんきょしょうがた
(mdoc)

はいぷ先生しょうめいしょの かたちは この 2つだけ! そして ワレットくんは りょうほう よめるように しておくこと。フクロウさんは すきな ほうで つくって いいよ。

おとなのことばクレデンシャルフォーマットは IETF SD-JWT VC(dc+sd-jwt)と ISO mdoc(mso_mdoc)の 2 つ。Wallet は両対応が MUST、Issuer/Verifier は選択可。旧識別子 vc+sd-jwt は dc+sd-jwt へ変更されたので既存実装は要修正です。
おやくそく その2

おへんじは まほうの ふうとうに いれて

はいぷ先生しょうめいしょを わたすときは、そのまま わたしちゃ ダメ。ワンだーさんだけが あけられる、まほうの ふうとうに いれるんだ。とちゅうで だれかに のぞかれても、なかみは ぜったい みえないよ。

ワレットくんふうとうの かぎは、ワンだーさんが さいしょに くれるんだね!

おとなのことば提示レスポンスは response_mode=direct_post.jwt で、Verifier の公開鍵(client_metadata で提供)宛てに JWE 暗号化(ECDH-ES)して送ることが必須。TLS の内側(プロキシやアクセスログ)にも属性を平文で残さないためです。
おやくそく その3

「みせて」と いうひとは みぶんしょうを みせてね

ワンだーさん「しょうめいしょ みせて」って おねがいするときは、ぼくの みぶんしょうと サインも いっしょに つけるワン。

ワレットくんほんものの もんばんさんだ! ニセモノに だまされて わたしちゃう しんぱいが ないね!

おとなのことばVerifier の提示リクエストは署名付きリクエスト(JAR)が必須で、x5c ヘッダの X.509 証明書チェーンで身元を証明します。client_id は x509_san_dns: / x509_hash: などの X.509 系プレフィックスを使用。ウォレットはトラストアンカーと照合してからユーザーに提示内容を見せます(フィッシング対策)。
おやくそく その4

ほしいものだけ きいてね

ワンだーさん「ぜんぶ みせて」じゃなくて、『おとなかどうか』だけ おしえて、って きくワン。

ワレットくんおなまえも たんじょうびも みせなくて いいんだ! ひみつが まもれて うれしいな。

はいぷ先生ききかたの ことばも、ルールブックで 1つに きめてあるよ。

おとなのことば要求クエリは DCQL(dcql_query)に一本化(旧 presentation_definition は OID4VP 1.0 で廃止)。SD-JWT の選択的開示と組み合わせて、必要最小限のクレームだけを提示させます(データ最小化)。
おやくそく その5

たいせつな かぎは きんこの なかで

はいぷ先生しょうめいしょと ペアになる ひみつの かぎは、スマホの なかの こわれない きんこで つくって、そとに ださないこと。

はいぷ先生そして フクロウさんに 「かぎは きんこに あるよ」「ぼくは ほんものの ワレットだよ」って しょうめいしてから カードを もらうんだ。

おとなのことば発行時は Wallet Attestation(正規ウォレットであることの証明=クライアント認証)と Key Attestation(鍵がセキュアエレメント等 WSCD で保管されている証明)が要求されます。加えてアクセストークンは DPoP(RFC 9449)で鍵に紐づけ、PAR + PKCE(S256)も必須です。

なくしたカードは 「むこうリスト」へ

フクロウさんカードを なくしたり、かいしゃを やめたりしたら、わたしが リストの しるしを 〇から ✕に かえるよ。

ワンだーさんぼくは その リストを みるだけで、「この カードは もう つかえないな」って すぐ わかるワン。フクロウさんに でんわしなくて いいから、だれが どこで カードを つかったかも バレないんだ。

おとなのことば失効管理は IETF Token Status List。VC 内の status クレームが指すビット列を Verifier が参照します。個別問い合わせが不要なため、Issuer に利用状況が漏れにくいプライバシー配慮型の設計です。

✦ ✦

ナレーションここからは あたらしい おともだち、おつかいロボットの「エージェントくん」の おはなし。じつは さいごに、はいぷ先生の まほうとも つながるんだよ。

だい2わ・その2

AIエージェントって なあに?

エージェントくんぼくは おしゃべりだけの AI じゃないよ。「くつを かってきて」って たのまれたら、じぶんで かんがえて、しらべて、おみせに いって、かってくるところまで やるんだ!

ワレットくんこたえる だけじゃなくて、さいごまで やりとげるのが エージェントなんだね!

おとなのことばAI エージェント = LLM(頭脳)+ 計画・記憶 + ツール呼び出し(手足)+ 実行ループ。「目標を渡すと自律的にやり遂げる」システムです。チャット AI との違いは「道具を使って実世界に働きかけ、結果を確認しながら進む」こと。
だい2わ・その3

どうぐばこの きょうつうコネクタ

エージェントくんぼくの どうぐばこは、どんな どうぐでも おなじ さしこみぐちで つながるんだ。あたらしい どうぐも すぐ つかえるよ。

エージェントくんそれから、なかまの エージェントと きょうりょくするときの あいさつの しかたも きまってるんだ。

おとなのことばツール接続の標準が MCP(Model Context Protocol、「AI 界の USB-C」)、エージェント同士の連携標準が A2A(Agent2Agent)。役割分担された標準群がエージェントを支えています。
だい2わ・その4

たいへん! おみせの ことばが バラバラ!

エージェントくんくつやさんに いったら、おみせごとに ちゅうもんの しかたが ぜんぶ ちがうんだ…… 100 けんの おみせが あったら、100 とおり おぼえなきゃ……。

ナレーションおみせも こまっていました。「この ロボット、ほんとうに おうちのひとに たのまれたの……?」

おとなのことばエージェント経由の買い物(エージェンティックコマース)では、EC 各社の API がバラバラで個別対応が必要でした。店側も「正規のエージェントか」「本人の許可があるか」を確認できない。だい1わの「ルールがバラバラ問題」と同じ構図です。
だい2わ・その5

おかいものの きょうつうご「UCP」とうじょう!

✦ ✦

ナレーション2026ねん 1がつ、せかいじゅうの おみせと ITのかいしゃが あつまって、「おかいものの きょうつうご」= UCP を つくりました。

エージェントくんどのおみせでも、「なにが できる?」→「しなもの みせて」→「カートに いれて」→「おかいけい!」が おなじ ことばで つうじるんだ!

おとなのことばUCP(Universal Commerce Protocol)は Google が 2026 年 1 月に NRF で発表したオープン仕様。Shopify・Walmart・Target など 20 社超が参加。店は「ディスカバリマニフェスト(できることリスト)」を公開し、カタログ検索 → カート → チェックアウト → 注文管理までを標準化。通信は REST / MCP / A2A のどれでも運べます。
だい2わ・その6

おつかいの あんぜんそうち

エージェントくんおみせに いくときは、なまえを なのって、サインを つけて、「おなじ ちゅうもんを 2かい しちゃう」ことも ないように するんだ。

ナレーションうっかりも いたずらも、しくみで ふせぐのが おやくそくです。

おとなのことばUCP のリクエストには必須ヘッダがあります:UCP-Agent(身元)、リクエスト署名(改ざん検知)、idempotency-key(二重実行防止)、request-id(トレース)。リトライしても注文は 1 回だけ実行されます。
だい2わ・その7

「ほんとうに たのまれたの?」は まほうのメモで

✦ ✦

エージェントくんおかいけいの まえに、「くつを 1まんえんまでで かっていいよ」って おうちのひとが サインした メモを みせるんだ。これで おみせも あんしん!

はいぷ先生きづいたかな? その サインつきメモは、だい1わの しょうめいしょ(VC)と おなじ まほうなんだよ。

おとなのことば支払い委任の証明は AP2(Agent Payments Protocol)のマンデート=「何を・いくらまで」というユーザー承認への電子署名つき委任状で、Verifiable Credential ベース。UCP ではチェックアウトの AP2 Mandates 拡張として使われます。VC/VP 検証の技術がエージェント時代の信頼インフラになる接点です。
だい2わ・ふろく
