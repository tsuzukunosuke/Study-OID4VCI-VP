# 絵本(紙芝居)スタイルガイド

このリポジトリの学習用「紙芝居(かみしばい)」HTML を作るときの方針メモです。
第6話(docs/13)以降はこの方針に従います。

## 対象読者・文体

- **対象年齢:小学5年生くらい**(10〜11歳)。専門知識は前提にしないが、子どもだましにはしない。
- **漢字は多めでよい**。5年生までに習う程度の漢字＋ふりがな無しで読める範囲を基本にしつつ、
  技術用語(発行者・検証者・署名・公開鍵・秘密鍵・選択的開示・符号化 など)は漢字で書く。
  難しい語は初出時にひとことで意味を添える。

## 内容の深さ

- **「大まかな概要 → 具体的な中身」で完全理解を促す**構成にする。
  - まず全体像(登場人物・ゴール・流れの地図)を見せる。
  - 次に一つずつ、具体的に掘り下げる。
- **サンプルデータを載せてよい**(JSON / JWT / ハッシュ値など。値はダミーで、長い文字列は「…」で省略)。
- **手順の粒度は細かくてよい**。1つの処理を複数ステップに分解して、
  「何を・どういう順番で・どう変換するか」を省略せず示す。
  - 例(KB-JWT の作成):VC を持つ → ペイロードの `_sd_alg` でハッシュ算法を確認 →
    提示部分(発行者JWT〜選んだ開示〜)をバイト列にする → ハッシュ化 → Base64url 符号化(= `sd_hash`) →
    `sd_hash`＋`aud`＋`nonce`＋`iat` でペイロードを作る → `typ:kb+jwt`＋`alg` でヘッダを作る →
    署名して KB-JWT を完成 → 末尾に連結して VP にする。
- **ページ数は多くてよい**(15〜20ページ以上でも可)。

## 正確さ

- 仕様(OID4VCI / OID4VP / SD-JWT VC / HAIP など)に**技術的に忠実**であること。
  やさしく言い換えても、事実(順序・何をハッシュするか・誰が署名するか等)は正確に。
- 学習者が持っている理解を確認・補正する「ポイント」欄を適宜置く。

## 見た目・操作(既存シリーズと統一)

- 木枠の紙芝居ステージ、「はいぷ先生」ほかの共通キャラクター、ページ送り(ボタン/矢印キー)、
  自動再生、`prefers-reduced-motion` 対応、各ページの「おとなのことば」欄(技術用語への対応)。
- 単一 HTML ファイル・自己完結(外部依存なし)。`docs/NN_*.html` として保存し、README に追記。
