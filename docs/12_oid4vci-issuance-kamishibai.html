だい5わ・その1

しょうめいしょが おさいふに とどくまで

✦✦

はいぷ先生きょうは、しょうめいしょ(VC)が どうやって スマホの おさいふに とどくかの おはなし。この 「とどけかたの ルール」を OID4VCIって いうんだ。じゅんばんに みていこう!

おとなのことばOID4VCI(OpenID for Verifiable Credential Issuance)= VC を発行者からウォレットへ発行するためのプロトコル。OAuth 2.0 を土台にしています。本編は発行の流れを順に追います。
だい5わ・その2

とうじょう人物

はっこうしゃ
(フクロウさん)
おさいふ
(ワレットくん)
きみ
(もちぬし)

はっこうしゃしょうめいしょを つくって わたす人(学校や 会社や 役所)。

おさいふしょうめいしょを うけとって、スマホの中に しまっておくアプリ。

きみしょうめいしょの もちぬし(本人)。おさいふを そうさするよ。

おとなのことばIssuer(発行者)/ Wallet(ホルダーのアプリ)/ Holder(あなた=もちぬし)。発行者は「認可サーバー+Credential Endpoint」を持つサーバーです。
STEP1

「しょうめいしょ あげるよ!」の おさそい

おさそいQR

はっこうしゃきみに しょうめいしょを あげたいな。この QRコードを おさいふで よみとってね!

ナレーションこの おさそいには、「どこの 発行者か」「どんな しょうめいしょか」が 書いてあります。

おとなのことばCredential Offer(発行の案内)。QR やリンクで渡され、credential_issuer(発行者URL)と credential_configuration_ids(どのクレデンシャルか)、grants(どの入口を使うか)を含みます。
STEP2

発行者の「できることリスト」を みる

おさいふまず 発行者の 「じこしょうかい(できることリスト)」を みてみよう。どの まどぐちに、どうやって いけば いいかが 書いてある!

おとなのことばIssuer メタデータ(/.well-known/openid-credential-issuer)。credential_endpoint・nonce_endpoint・credential_configurations_supported(発行できる種類・形式・必要な proof)などが載った「発行者のカタログ」です。
STEP3

2つの 入口(フロー)

かんたんじぜんに 本人確認ずみ

まどぐちの人が もう「きみは 本人だ」と わかっている。みじかい あいことばと、4けたの PINを いれるだけ。
Pre-Authorized Code Flow

その場でいまから ログイン

まどぐちで ログインして「わたしていい?」に どうい。ふつうの ログインと おなじ。
Authorization Code Flow

はいぷ先生この おはなしでは、かんたんな ほう(じぜんに 本人確認ずみ)で すすめるよ!

おとなのことば発行フローは 2 種類。Pre-Authorized Code Flow(事前に本人確認済み・pre-authorized_code+ 別送 PIN の tx_code)と Authorization Code Flow(その場で認証・PKCE)。どちらを使うかは Credential Offer の grants で示されます。
STEP4

あいことばを みせて「きっぷ」を もらう

おさいふあいことば(pre-authorized_code)と、きみが いれた PINを みせるよ。

はっこうしゃたしかに 本人だね。はい、きっぷ(アクセストークン)を どうぞ。これが あれば しょうめいしょを うけとれるよ。

おとなのことばToken Endpoint。grant_type=...pre-authorized_code + pre-authorized_code + tx_code(PIN)を送り、アクセストークンを得ます。以降このトークンで Credential Endpoint にアクセスします。
STEP5

つかいすての 合言葉(c_nonce)

おさいふしょうめいしょを もらう まえに、つかいすての 合言葉を ください。

はっこうしゃはい、こんかいだけの 合言葉(c_nonce)だよ。これを つぎで つかってね。

おとなのことばNonce Endpoint から使い捨てのチャレンジ c_nonce を取得。次の proof(鍵所有証明)に埋め込むことで、使い回し(リプレイ)を防ぎます。
STEP6

「これ ぼくの かぎだよ」の しょうこ(proof)

おさいふぼくの ひみつの かぎで、さっきの 合言葉に サインする。これが 「この かぎの もちぬしは ぼくだよ」の しょうこ(proof)だ!

はいぷ先生この proof の 公開鍵が、あとで しょうめいしょの 中に 入るんだ。だから「その しょうめいしょは この おさいふ専用」に なるよ。

おとなのことばproof(鍵所有証明)。ウォレットが自分の鍵で c_nonce を含む JWT に署名(typ: openid4vci-proof+jwt)。この公開鍵が発行される VC の cnf に入り、Key Binding(持ち主しか使えない状態)になります。
STEP7

しょうめいしょ(VC)、とうちゃく!

✦✦

おさいふきっぷ(トークン)と しょうこ(proof)を みせるよ。しょうめいしょを ください!

はっこうしゃぜんぶ そろってるね。はい、発行者の はんこ(でんししょめい)を おした しょうめいしょだよ。おめでとう!

おとなのことばCredential Endpoint。アクセストークン + proofs を送り、発行者が署名した VC(dc+sd-jwt 等)を credentials で受領。VC には発行者の署名とウォレットの公開鍵(cnf)が入っています。
STEP7の べつパターン

すぐ 出せない ときは…

はっこうしゃごめんね、いまは まだ じゅんびちゅう。この ひきかえ番号(transaction_id)を もって、あとで また きてね。

おさいふわかった! じゃあ あとで 「ひきかえ まどぐち」に とりに くるね。

おとなのことばその場で発行できない場合(人手の審査など)は、VC の代わりに transaction_id を返し、ウォレットは後で Deferred Credential Endpoint に取りに来ます。
STEP8

「ちゃんと もらえたよ!」の おれい通知

おさいふしょうめいしょ、ちゃんと しまえたよ! 「うけとり せいこう」って 発行者に おしらせしておくね。

はっこうしゃありがとう。これで 発行は かんりょう!

おとなのことばNotification Endpoint。ウォレットは「保存に成功した/失敗した/ユーザーが削除した」等を発行者へ通知でき、発行者は発行状況を把握できます。
